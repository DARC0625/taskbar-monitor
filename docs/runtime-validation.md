# 실제 위젯 안정성 검사

0.4.1 후보는 작업표시줄에 표시하는 앱 자체의 갱신·재연결·자원 사용을 검사할 수 있습니다. 창 없는 probe와 Windows Server CI의 결과는 [자동 검사](testing.md), 별도 Windows 11 화면 검사 범위는 [호환성 매트릭스](compatibility.md)를 참고하세요.

## 수집 중단과 종료

수집기는 CPU/RAM, GPU, 디스크, NPU의 네 개 고정 작업 스레드를 사용합니다. GPU와 디스크는 각각 자신의 PDH 쿼리를 소유하고, NPU는 별도 DXCore 경로를 사용합니다. 느린 센서의 호출이 돌아오지 않아도 다른 수집기가 같은 호출 뒤에서 기다리지 않습니다. 실패한 공급자는 각자의 경로에서 30초 간격으로 다시 준비하며, 막힌 호출을 대체할 스레드를 계속 만들지 않습니다.

종료 시 새 결과 게시와 UI 알림을 중단하고, 작업 스레드 종료를 기다리는 전체 예산을 250ms로 제한합니다. 끝나지 않은 네이티브 호출은 강제로 종료하지 않습니다. 해당 스레드가 소유한 자원은 호출이 돌아온 뒤 정리하며, 늦은 결과는 폐기합니다. 이 예산은 수집기 join 대기 기준입니다. Windows 스케줄링, 그래픽 자원 해제, 프로세스 전체 종료 시간이 항상 250ms 이하라는 보장은 아닙니다. 알림 callback은 잠금을 재진입하지 않는 짧은 `PostMessage` 호출이어야 합니다.

회귀 테스트는 가짜 수집기를 의도적으로 대기시켜 다른 센서의 진행, 세대 변경 후 늦은 결과 폐기, 종료 예산과 스레드 수 제한을 확인합니다. 이 테스트가 실제 드라이버의 모든 장애를 재현하지는 않습니다.

장치 재탐색이 오래 걸렸을 때는 완료 후 시각으로 수집 기준을 다시 잡습니다. 재탐색에 든 시간을 다음 절전/중단 판정에 재사용하여 첫 표본 준비만 반복하지 않도록 했습니다. 창 종료 시에는 컨트롤 창이 아직 유효할 때 알림을 먼저 해제합니다.

## GUI 진단 보고서

위젯을 `--report <새 JSON 경로>`와 함께 실행하면 기존 UI 타이머에서 5초 간격으로 자기 프로세스의 CPU 시간·메모리·핸들·GDI/USER 개체 수를 읽습니다. `--seconds`로 최대 86400초 후 자연 종료할 수 있습니다. 일반 실행에서는 진단 수집과 표본 버퍼를 만들지 않습니다.

- 지연: 최근 성공적으로 그린 서로 다른 CPU 표본 1200개로 p50/p95를 계산합니다. 전체 기간의 표본 수와 최대 지연은 별도로 유지합니다.
- 자원: 최근 720개 표본과 전체 기간의 관측 범위를 보관합니다. 5초 주기라면 최근 약 한 시간이며, 강제 보고·타이머 지연에 따라 실제 범위는 달라집니다.
- 복구: 재연결과 렌더러 교체 횟수, 그리기 실패, 마지막 성공 시각을 남깁니다. 교체된 렌더러의 통계도 누적합니다.
- 종료: 창과 렌더러를 해제하기 직전 보고서를 작성하여 종료 후 무효화된 창을 정상 실행 상태로 해석하지 않습니다.

지연은 **CPU 측정 완료부터 EndDraw 및 DXGI Present 반환까지**입니다. 실제 화면에 빛이 표시된 시간, 그리지 못한 표본의 지연, 센서 자체 정확도를 뜻하지 않습니다. `IsWindowVisible`과 부모/DPI 정보 역시 실제 글자 잘림이나 다른 창에 가린 픽셀을 판정하지 않습니다. 메모리 최대값은 주기적으로 읽은 표본의 최대값이며 연속 관측 최대값이 아닙니다.

원본 보고서에는 장치 설명과 로컬 경로가 들어갈 수 있습니다. 공개할 때는 필요한 카운터·상태·환경 범주만 추린 요약을 사용하세요.

## 재연결 및 장시간 관찰

[`test-widget-runtime.ps1`](../scripts/test-widget-runtime.ps1)은 실행 파일을 새 portable 검사 폴더에 복사하여 짧은 GUI 실행을 검사합니다. 기존 위젯이 실행 중이면 시작하지 않습니다. 앱 자신의 CLI로 재연결과 보고를 요청하고 자연 종료를 기다립니다. 설치·자동 시작·Explorer·배율·절전 설정은 바꾸지 않습니다. 실제 실행 옵션은 스크립트의 param 정의를 기준으로 합니다.

```powershell
./scripts/test-widget-runtime.ps1 -Executable target/release/taskbar-monitor.exe `
  -DurationSeconds 45 -ReattachCount 5 -PreferencesFile widget-test.json
```

설정 파일은 선택 사항이며 지정하면 복사본을 사용합니다. CLI의 `--target-pid`와 `--target-start-time` 쌍은 요청할 때와 수신할 때 모두 확인합니다. `--target-start-time`은 프로세스 생성 시각의 UTC FILETIME 정수입니다. 잘못된 대상은 비정상 종료 코드로 거절합니다. 검사 시간이 초과되면 유지해 둔 자기 자식 프로세스 핸들만 정리하며, 이 경우 검사는 실패입니다. 정상 종료가 수집기 단위 테스트의 250ms 예산 자체를 실측한 것으로 기록하지 않습니다.

[`watch-widget.ps1`](../scripts/watch-widget.ps1)은 명시한 기존 PID와 시작 시각을 확인하며 프로세스 자원을 읽기만 합니다. 위젯을 시작·종료하거나 UI 명령을 보내지 않습니다. 새 실행 폴더에 JSONL 관측 기록과 원자적으로 교체하는 JSON 요약을 저장하고, 시간·레코드 수·파일 크기 중 정해진 한계에 도달하면 끝냅니다. 예시의 PID와 경로는 해당 실행에서 얻은 값으로 지정하세요.

```powershell
./scripts/watch-widget.ps1 -TargetProcessId $widgetProcess.Id `
  -ExpectedStartTimeUtc $widgetProcess.StartTime.ToUniversalTime() `
  -StopAfterSeconds 86400 -IntervalSeconds 5 -OutputRoot target/soak-tests
```

CPU 평균은 전체 OS 논리 프로세서 수로 정규화한 구간 가중 평균입니다. p95는 유효 구간 표본으로 계산합니다. 메모리·핸들·스레드는 시작/끝/최소/최대와 관측 추이를 남깁니다. 고정 성능 합격선을 임의로 적용하거나 짧은 시작 구간의 증가를 누수로 단정하지 않습니다.

`running` 요약은 중간 기록입니다. `completed`도 요청한 관찰 시간이 끝났다는 뜻이므로 표본 수, 관찰 공백, 읽기 오류, 위젯 보고서를 함께 확인해야 합니다. 절전과 스케줄러 지연을 시간 간격만으로 확정하지 않으며, 공백을 정상 연속 관찰로 채워 넣지 않습니다. PID 재사용·프로세스 종료·출력 제한·오류로 끝나면 그 원인을 구분합니다.

## 배포 판단

24시간 관찰은 실제 경과 후 결과를 기록합니다. 짧은 GUI 성공이나 단위 테스트 성공을 24시간 안정성으로 표시하지 않습니다. 자동 재연결 명령은 살아 있는 Explorer에 위젯을 다시 연결하는 검사이며, 실제 Explorer 재시작·절전 복귀·DPI 변경·디자인별 화면 확인은 별도로 남깁니다. 이 수동 범위의 미확인 상태는 릴리스 게시 승인으로 대체할 수 없습니다.
